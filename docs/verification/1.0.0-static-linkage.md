# 1.0.0 candidate static verification: 1.21.2-1.21.3

On 2026-11-12 the locally built `third-person-readable-maps-1.0.0-mc1.21.2-1.21.3.jar` had SHA-256
`1b16c66cb32a7684645d5c28e423fc76244d47326ba3e4cce839ead8e01b2e75`. The current `verify_supported_apis.py` and shared
`game_linkage.py`/`jvm_linkage.py` were run against that exact JAR and every
Minecraft version declared for this group. All checks passed. Game client
artifacts and required game-provided libraries were checked against Mojang's
version metadata. The verifier checks packaged references, bytecode operation
kinds, staticness, relevant access and inheritance, descriptors, method handles,
and supported Mixin target and injection semantics. Fifteen controlled fixture
tests passed with JDK 25 on Linux. CI also runs the fixtures and verifier.

This is a static linkage check, not a complete JVM bytecode verifier or proof
of behavior for every possible transformed program. Protected receiver flow,
complex `invokespecial` selection, unsupported Mixin transformations, JDK and
Mixin library internals, and graphical behavior are not comprehensively proved.
The Java compiler's `--release` target and declared Fabric/Mixin dependencies
provide separate build-time checks. Runtime and independent acceptance remain
separate gates. Earlier 0.0.2 artifact evidence is historical and does not
certify this JAR. Windows and exact-commit hosted CI results must be checked on
the PR; this local Linux result does not imply they have passed.

The 2026-11-13 verifier follow-up also checks class literals and class-use
instructions in the effective Mixin target context, plus abstract/interface
instantiation and constructor method handles. Its 16 controlled fixtures
passed on JDK 25, including an inaccessible class-only reference accepted
by the previous check. The updated verifier was run against the same
identified 1.0.0 JAR on every declared version. These checks do not close
the remaining protected-receiver, `invokespecial` and complex-transform
limitations above; final source-bound runtime and CI evidence is separate.
