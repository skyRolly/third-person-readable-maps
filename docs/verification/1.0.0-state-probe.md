# Minecraft 1.14 texture and lighting state probe

The previous `0.0.2` candidate (`839f0982d11c0a0f95199e1486f7ece203acb7fe8f3e2dd309e9edec214ce5a5`)
and this worktree's `1.0.0` candidate (`5770c22a021f1c2fd74a80444fe759701f70c82a65fa03e9fd5e90154e701423`)
were installed separately on Minecraft 1.14 with Fabric Loader 0.20.1, Java 8,
and Linux Xorg/Mesa software rendering. Both joined a copied local world and
saved normally. The same test-only [probe source](state-1.0.0/StateProbeMixin.java),
[metadata](state-1.0.0/fabric.mod.json), and [configuration](state-1.0.0/state-probe.mixins.json)
were used in both runs; the probe JAR SHA-256 was
`2c26f17c0a524b652feba3c444cb4499009953856d5fbaa8c6de8a3ee1c5c2cc`.

For eight actual map-draw calls in one local arrangement, the diagnostic seeded
a distinct texture binding and alternated incoming lighting on and off. The
earlier JAR left a different texture bound on all eight calls; the new JAR
preserved the seeded binding, active texture unit, and incoming lighting state
on all eight. See [earlier samples](state-1.0.0/old-excerpt.txt),
[new samples](state-1.0.0/fixed-excerpt.txt), the [earlier scene](state-1.0.0/old-scene.png),
and [new scene](state-1.0.0/fixed-scene.png). The [local harness](state-1.0.0/run.py)
records the launch procedure. Portions of map terrain are visible in the new
scene, with foliage nearby.

## Repeat with two active texture units

A second [test-only probe](state-units-1.0.0/StateProbeMixin.java), SHA-256
`d83161521eeaf76913473d8167fa1a7fd6e8c44aca6f74bb197e5e4b1d338581`, repeated
the comparison while seeding bindings on texture units 0 and 1 and alternating
lighting. The [earlier JAR](state-units-1.0.0/old-excerpt.txt) changed the
seeded binding on all eight draws. The [new JAR](state-units-1.0.0/fixed-excerpt.txt)
preserved the active unit, binding and lighting in all eight draws. Both clients
saved normally; see the [new scene](state-units-1.0.0/fixed-scene.png),
[configuration](state-units-1.0.0/state-probe.mixins.json),
[metadata](state-units-1.0.0/fabric.mod.json), and [local harness](state-units-1.0.0/run.py).

These diagnostics do not cover every texture unit, exceptional exits, both
hands, untagged maps, later held items or entity features. It is neither
independent visual acceptance nor hardware-GPU or multiplayer evidence. The
separate map-ID change and the remaining four 1.14 versions require their own
targeted checks on the final artifact.
