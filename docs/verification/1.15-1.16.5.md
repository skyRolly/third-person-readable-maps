# Installed-client smoke tests: Minecraft 1.15–1.16.5

The identical intermediary JAR built from implementation commit
`84dde45175c0ca154b44a1acd4efe30d741d5077` had SHA-256
`d30a2a682699e881903275ce373d79374b1475e5dff10e7b3e66d364819b13de`.
It was installed on each version with Fabric Loader 0.20.1, Java 8
(8.0.504+1), Linux and a software Xorg/Mesa display. Every client applied its
required Mixin, joined the same single-player world, upgraded in order from
the 1.14 test, and displayed generated map terrain in these arrangements:

These are partial local-player smoke tests. Additional per-version left-handed,
opposite-hand, untagged-item and first-person comparisons are listed below;
unlisted versions and cases remain NOT RUN. Missing-data null behavior, complete
lighting, movement,
first-person regression, multiplayer and independent visual acceptance remain
outstanding. The software display had no audio device and the offline clients
could not retrieve online profiles. Complete the full runtime matrix on the
final artifact before release.

## Unsupported-version launch

A headless Linux Fabric Loader 0.20.1 launch installed this same JAR into a
Minecraft 1.17 client using Java 16. Fabric exited with status 1 during mod
resolution and explicitly identified 1.17 as unsupported; Mixin initialization
was not reached. The [launch log](1.17-unsupported-neighbor.txt) records the
actual rejection. This checks the declared version guard for that client, not
a forced installation with the guard bypassed. A Java 7 launch is recorded below.

## Java 7 launch

A headless Linux launch placed the same candidate JAR in a Minecraft 1.15
Fabric Loader 0.20.1 profile using Zulu OpenJDK 7.0.352. The process exited
with status 1 because the loader's entry class requires class-file version 52
(Java 8); [the launch log](1.15-java7-rejected.txt) records the error. The
loader stopped before it could inspect the mod's own metadata, so this is a
loader/runtime rejection rather than an independent test of that metadata.

The Java 7 distribution's SHA-256 was checked against [vendor metadata](https://api.azul.com/metadata/v1/zulu/packages/f436b3cb-0115-4814-b7fa-e180747bd68f):
`8a7387c1ed151474301b6553c6046f865dc6c1e1890bcf106acc2780c55727c8`.

## Additional 1.15 left-handed and first-person checks

With the same candidate JAR, the left-handed local client displayed terrain in
the [main hand](1.15-extra-left-main.png), [off hand](1.15-extra-left-off.png),
and [both hands](1.15-extra-left-both.png). Terrain remained visible with stone
in the opposite hand for the [main-hand map](1.15-extra-left-main-stone.png)
and [off-hand map](1.15-extra-left-off-stone.png). An [untagged filled map](1.15-extra-left-untagged.png)
remained usable without a crash. Older clients can resolve a missing map ID to
map 0, so this does not establish missing data. A separate
[fault-injection diagnostic](1.15-missing-data-probe.md) exercised the null path.

The [candidate first-person view](1.15-extra-firstperson.png) was compared
with the same Fabric Loader profile [without the candidate JAR](1.15-extra-firstperson-no-mod.png)
using a copy of the saved world. In the 540 by 440 pixel map crop at `(370, 60)`
the mean absolute channel difference was 0.593 on a 0–255 scale;
100.000% of pixels differed by at most 10 levels per channel,
with a maximum of 9. The views were not pixel-identical, and this single
comparison does not establish complete first-person regression coverage.
