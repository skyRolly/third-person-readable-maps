# 1.17–1.19.2 forced missing-data diagnostic

The ordinary untagged-map smoke does not establish missing data: a client may
resolve an absent map ID to map 0. This separate test-only helper redirects the
map-state lookup inside the installed candidate renderer to return `null`; it
does not simulate all ways a map state can be absent.

The installed distributable was the unchanged candidate JAR with SHA-256
`aee00518a1a5b3c31cf794063ac685aa2675ac0b719f11d2b50d0ec8ccf351e6`. A second, test-only diagnostic mod used Fabric Loader
0.20.1 and Linux software rendering. Its JAR SHA-256 was `8dc6f62770813201051406bc3edd4294f01fa61924d33b108ac1cce0d8fa8689`;
it is not part of the distributable. Its [source](missing-probe/MissingDataProbeMixin.java),
[mod metadata](missing-probe/fabric.mod.json), and [Mixin configuration](missing-probe/missing-data-probe.mixins.json)
are retained. Minecraft 1.17 and 1.17.1 used Java 16; 1.18–1.19.2 used Java 17.

These are single-layout fault injections. Ordinary missing-data scenarios,
complete movement and lighting, independent acceptance and multiplayer remain
outstanding.

## 1.17 forced-null draw

The helper returned `null` for eight map-state lookups and recorded eight
completed draws; the client then saved and exited without a Mixin or linkage
error. The [log excerpt](missing-probe/1.17-probe-excerpt.txt) and
[screenshot](missing-probe/1.17-forced-null.png) retain the result. This is
one injected null path in one local pose, not ordinary missing-data coverage
or full graphical acceptance.
