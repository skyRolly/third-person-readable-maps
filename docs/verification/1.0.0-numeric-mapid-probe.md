# Minecraft 1.19.3 numeric map identity probe

On Minecraft 1.19.3 with Fabric Loader 0.20.1, Java 17 and Linux Xorg/Mesa software rendering, this controlled diagnostic compared an earlier 1.0.0 artifact (`cb5c1e04f33ad1fc572f72f01da6f15ba3c151e520df651b9638ae8a2afa4597`) with the corrected artifact (`4282166c4250d35db2cc794de986ae4c3de9438e8d7932991778454bdefff1c1`). The copied world contained map-zero and map-two data. A separately installed [test-only Mixin](numeric-mapid-1.0.0/MapIdProbeMixin.java), SHA-256 `8251fd0243d7cd8d40f4cae921940747179406129e36e77f35fa6ef28b11d45c`, substituted copied stacks and observed the real game lookup without changing the held inventory item.

| Identity | Earlier candidate | Corrected candidate |
|---|---|---|
| Absent tag, empty tag or nonnumeric text | Lookup returned no data | No lookup |
| Fractional `0.5`, overflowing long `4294967296`, or NaN | Lookup returned map-zero data | No lookup |
| Explicit integer zero or short zero | Lookup returned map-zero data | Lookup returned map-zero data |
| Explicit integer map 2 | Lookup returned data | Lookup returned data |
| Valid but unavailable map 9999 | Lookup returned no data | Lookup returned no data |

Each case ran three times. See [earlier samples](numeric-mapid-1.0.0/old-excerpt.txt), [corrected samples](numeric-mapid-1.0.0/fixed-excerpt.txt), the [corrected scene](numeric-mapid-1.0.0/fixed-scene.png), [probe metadata](numeric-mapid-1.0.0/fabric.mod.json), [Mixin configuration](numeric-mapid-1.0.0/mapid-probe.mixins.json) and [local harness](numeric-mapid-1.0.0/run.py). Numeric integral IDs within Java's integer range remain valid, including zero; the renderer does not mutate the stack.

This is a diagnostic for one game version and local scene, not full hand/pose acceptance, naturally delayed multiplayer data, hardware-GPU validation or independent visual review. Other declared versions require their own final-artifact runtime evidence.
