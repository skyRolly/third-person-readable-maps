# Installed-client smoke tests: Minecraft 1.17–1.19.2

The identical intermediary JAR built from implementation commit
`a12c56cc742ec0b0c3ab26619bddf110482b95d6` had SHA-256
`aee00518a1a5b3c31cf794063ac685aa2675ac0b719f11d2b50d0ec8ccf351e6`.
It was installed with Fabric Loader 0.20.1, Linux and software Xorg/Mesa.
Minecraft 1.17 and 1.17.1 used Java 16 (16.0.2+7); 1.18–1.19.2 used
Java 17 (17.0.21+9). Every client applied its required Mixin, joined a
local single-player world and displayed generated map terrain in these
arrangements. The 1.19.1 run was repeated from an earlier world backup after
the first automation pass captured first-person rather than third-person views:

opposite-hand, untagged-item and first-person comparisons are listed below;

outstanding. The software display had no audio device and the offline clients
could not retrieve online profiles. Complete the full runtime matrix on the
final artifact before release.

## Unsupported-version launch

A headless Linux Fabric Loader 0.20.1 launch installed this same JAR into a
Minecraft 1.19.3 client using Java 17. Fabric exited with status 1 during mod
resolution and explicitly identified 1.19.3 as unsupported; Mixin initialization
was not reached. The [launch log](1.19.3-unsupported-neighbor.txt) records the
actual rejection. This checks the declared version guard for that client, not
a forced installation with the guard bypassed.

## Wrong-Java launch

A headless Linux Fabric Loader 0.20.1 launch installed the same JAR into a
Minecraft 1.17 client using Java 8. Fabric exited with status 1 during mod
resolution and explicitly reported that the mod requires Java 16 or later;
Mixin initialization was not reached. The [launch log](1.17-java8-rejected.txt)
records this rejection. Other unsupported runtimes were not tested.

## Additional 1.17 left-handed and first-person checks

With the same candidate JAR, the left-handed local client displayed terrain in
the [main hand](1.17-extra-left-main.png), [off hand](1.17-extra-left-off.png),
and [both hands](1.17-extra-left-both.png). Terrain remained visible with stone
in the opposite hand for the [main-hand map](1.17-extra-left-main-stone.png)
and [off-hand map](1.17-extra-left-off-stone.png). An [untagged filled map](1.17-extra-left-untagged.png)
remained usable without a crash. Older clients can resolve a missing map ID to
map 0, so this does not establish the missing-data null path, which remains NOT RUN.

The [candidate first-person view](1.17-extra-firstperson.png) was compared
with the same Fabric Loader profile [without the candidate JAR](1.17-extra-firstperson-no-mod.png)
using a copy of the saved world. In the 540 by 440 pixel map crop at `(370, 60)`
the mean absolute channel difference was 1.335 on a 0–255 scale;
95.525% of pixels differed by at most 10 levels per channel,
with a maximum of 22. The views were not pixel-identical, and this single
comparison does not establish complete first-person regression coverage.

## 1.17 local walking, sneaking and lighting smoke

In a separate local world on Linux software rendering, the unchanged candidate
JAR was tested with Fabric Loader 0.20.1 and the version's Java runtime. The
player was placed on a cleared stone platform and moved horizontally 10.20
blocks from `[5.5, 81, -62.5]` to `[5.5, 81.0, -52.30000001192093]`. A [standing day view](movement/1.17-standing-day.png)
and three frames while holding forward ([1](movement/1.17-walking-1.png),
[2](movement/1.17-walking-2.png), [3](movement/1.17-walking-3.png)) were captured;
the [sneaking view](movement/1.17-sneaking.png) and the
[night view](movement/1.17-night.png) are retained for visual inspection.
The raw color counts include parts of the player and do not establish map
visibility. Later views may be obscured by the terrain wall. See the
[measurement](movement/1.17-movement.json) and [log excerpt](movement/1.17-movement-excerpt.txt).
These are single local-layout smoke checks, not complete movement, lighting,
multiplayer or independent visual acceptance.
