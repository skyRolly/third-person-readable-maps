# Installed-client smoke test: Minecraft 1.19.3

The intermediary JAR built from implementation commit
`c9ca3b5f05768017a197116919f22e2a967a8d01` had SHA-256
`f7288ad9a7f73f718176db15f185bab10d8a02548b02e2f4a943aac06f0db16b`.
It was installed with Fabric Loader 0.20.1, Java 17 (17.0.21+9), Linux and a
software Xorg/Mesa display. The client applied its required Mixin, joined a
local single-player world, and displayed terrain on held maps in the
[main hand](1.19.3-mainhand.png), [off hand](1.19.3-offhand.png), and
[both hands](1.19.3-both-hands.png).

These are partial local-player smoke checks. Complete lighting, movement,
first-person regression comparisons, multiplayer and independent visual
acceptance remain outstanding. The software display had no audio device and the offline client
could not retrieve online profile data. Complete the full runtime matrix on
the final artifact before release.

## Additional left-handed local checks

With the same JAR and environment, the `mainHand` option was set to `left`.
Terrain appeared in the [main hand](1.19.3-left-mainhand.png),
[off hand](1.19.3-left-offhand.png), and [both hands](1.19.3-left-both.png).
With a stone in the opposite hand, terrain appeared for a [main-hand map](1.19.3-left-main-stone-off.png)
and an [off-hand map](1.19.3-left-off-stone-main.png). A filled-map item
created without map data showed a [blank face](1.19.3-left-missing-map.png)
and the client remained running. [First-person terrain](1.19.3-left-firstperson.png)
was also observed; a later controlled comparison is recorded below.
These views do not establish full alignment, movement, lighting, or multiplayer
behavior.

## Local multiplayer connection attempt

A second 1.19.3 client with the same JAR attempted to join the test world over
loopback after it was opened to LAN. The server was reached, but the observer
was disconnected because Minecraft's authentication service was unavailable;
the [client message](1.19.3-lan-auth-unavailable.png) records the failure.
No remote-player map rendering was observed, so multiplayer remains NOT RUN.

## Unsupported runtime and version launches

Headless Linux launches with Fabric Loader 0.20.1 installed the same JAR in
two incompatible environments. Minecraft 1.19.3 with Java 16 was rejected
because the mod requires Java 17 or later; see the [wrong-Java log](1.19.3-java16-rejected.txt).
Minecraft 1.19.4 with Java 17 was rejected because only 1.19.3 is permitted;
see the [unsupported-version log](1.19.4-unsupported-neighbor.txt). Both exited
with status 1 during mod resolution before Mixin initialization. An initial
1.19.4 attempt was inconclusive because its profile was being reinstalled;
the retained log is the repeat after the verified client was available. These
checks do not cover every unsupported runtime or a bypassed metadata guard.

## Controlled first-person comparison

Two copies of the same saved world were opened at position `[5.5, 86.0, -62.5]`
with Fabric Loader 0.20.1 and Java 17; one installed the candidate and the other
did not. Time was fixed to day and the player position was unchanged in both
runs. In the 540 by 440 map crop at `(370, 60)`, the
[candidate](1.19.3-firstperson-control-candidate.png) and
[no-mod view](1.19.3-firstperson-control-no-mod.png) had a mean absolute channel
difference of 0.425 on a 0–255 scale;
100.000% of pixels differed by at most 10 levels per channel,
with a maximum of 7. The views were not pixel-identical.
This one comparison does not establish complete first-person regression coverage.

[Additional short walking checks](short-walking-smoke.md) record per-version local movement views.
