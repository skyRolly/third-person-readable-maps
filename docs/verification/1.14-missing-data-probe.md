# 1.14–1.14.4 forced missing-data diagnostic

The ordinary untagged-map smoke is not a missing-data test: these clients can
resolve an absent map ID to map 0, and their server can create missing map state
during inventory ticks. This separate fault-injection test redirects only the
map-state lookup inside the installed candidate's draw method to return `null`.
It does not simulate all ways a map state can be absent.

The installed distributable was the unchanged Java 8 candidate JAR with SHA-256
`839f0982d11c0a0f95199e1486f7ece203acb7fe8f3e2dd309e9edec214ce5a5`.
A second, test-only diagnostic mod used Fabric Loader 0.20.1, Java 8 and Linux
software rendering; it is not part of the distributable. Its JAR SHA-256 was
`75c7b6fb99417172a13f086c6b39c734f3fae3c8d2a3ac52ee13cbbf8140f526`. The exact [probe source](missing-probe/MissingDataProbeMixin.java),
[mod metadata](missing-probe/fabric.mod.json), and [Mixin config](missing-probe/missing-data-probe.mixins.json)
are retained for review.

| Minecraft | Forced-null installed-client diagnostic |
|---|---|
| 1.14 | PASS for one local left-handed main-hand layout |
| 1.14.1 | NOT RUN |
| 1.14.2 | NOT RUN |
| 1.14.3 | NOT RUN |
| 1.14.4 | NOT RUN |

For 1.14, the diagnostic returned `null` for eight map-state lookups and logged
eight completed draws; the client saved the world and exited without a Mixin or
linkage error. The [log excerpt](missing-probe/1.14-probe-excerpt.txt) retains
the individual samples. The [screenshot](missing-probe/1.14-forced-null.png)
shows the unfilled face; nearby leaves partly obscure it. This is one injected
null path in one pose, not ordinary missing-data or full graphical acceptance.

The first helper attempt used an invalid Mixin selector and did not yield a
valid result. Its [error excerpt](missing-probe/invalid-selector-first-attempt.txt)
is retained; the selector was corrected before the successful retry. The error
was in the separate test helper, not the candidate JAR.
