# Revised 1.14 candidate: lighting-state fix

The revised intermediary JAR has SHA-256
`839f0982d11c0a0f95199e1486f7ece203acb7fe8f3e2dd309e9edec214ce5a5`. The previous JAR (`909b2299eed92d71c054bc9ddb4829235f560c657fab79a60f91a78354a06eec`) unconditionally enabled lighting
after drawing a map. Minecraft 1.14's outline pass disables lighting before
rendering entity features, so the previous code could change that pass's state.
The revised surface reads the incoming `GL_LIGHTING` state and restores the same
state after drawing, including on exceptional exit. The Mixin remains required.

The revised JAR passes the same Mixin descriptor and game API checks on all five
SHA-1-verified clients, plus an added check of the LWJGL reference against every
OpenGL library variant declared in each Mojang manifest. The retained
[static output](lighting-probe/static-linkage.txt) includes both 1.14.4 variants.

A temporary [diagnostic Mixin](lighting-probe/LightingProbeMixin.java), installed
alongside each JAR only for this test, alternated the incoming lighting state
on actual 1.14 map draws. The [previous JAR](lighting-probe/samples-old.txt)
left lighting enabled when it entered disabled; the [revised JAR](lighting-probe/samples-fixed.txt)
preserved both enabled and disabled inputs. Fabric Loader 0.20.1, Java 8 and a
Linux software-rendered local world were used. The diagnostic was compiled for Java 8 against the intermediary client, Sponge
Mixin and LWJGL 3.2.1; its local JAR SHA-256 was
`01a2cc154ca759f07987db4f931caf8ddce8bef56f14e99d840f7230e735779c`. It is not part of
the distributable JAR. This is a targeted state check, not complete graphical
or independent acceptance.

## Revised 1.14 local smoke

The unchanged revised JAR was installed with Fabric Loader 0.20.1 and Java 8
on Linux software rendering. Terrain appeared with a right-handed player in the
[main hand](lighting-fix/1.14-right-main.png), [off hand](lighting-fix/1.14-right-off.png),
and [both hands](lighting-fix/1.14-right-both.png); and with a left-handed player
in the [main hand](lighting-fix/1.14-left-main.png), [off hand](lighting-fix/1.14-left-off.png),
and [both hands](lighting-fix/1.14-left-both.png). With stone in the opposite hand,
terrain appeared for a [main-hand map](lighting-fix/1.14-left-main-stone.png) and
an [off-hand map](lighting-fix/1.14-left-off-stone.png). An [untagged filled map](lighting-fix/1.14-left-untagged.png)
did not crash; vanilla may resolve an absent map ID to map 0. A separate
[fault-injection diagnostic](1.14-missing-data-probe.md) exercised the null path.

A [candidate first-person view](lighting-fix/1.14-firstperson.png) and a
[no-mod view](lighting-fix/1.14-firstperson-no-mod.png) used a copy of the saved
world. In the 540 by 440 pixel map crop at `(370, 60)`, mean absolute channel
difference was 1.947 on a 0–255 scale;
88.712% of pixels differed by at most 10 levels per channel,
with a maximum of 31. The views were not pixel-identical;
this one comparison is not complete first-person regression coverage.

The images exceeded the comparison threshold; the result is inconclusive and does not identify the cause.
