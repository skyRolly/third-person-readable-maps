# Candidate verification: Minecraft 1.21.4–1.21.8

This is partial smoke testing, not release acceptance. Implementation source
commit `4b2e363c495640fa5ca305620c51c709a434ee2c` produced the same JAR in a
clean build and was installed unchanged on all five clients. SHA-256:
`26a28fb550132d07af415c41ccb82982937906ab991ad810406d2937b5e4e776`.

Environment: Linux x86-64, Debian OpenJDK 21.0.12.1, Fabric Loader 0.20.1,
Xorg dummy display with Mesa software GL, offline local single-player creative
world. The client could not reach account/Realms services and had no audio
device. This is not evidence of multiplayer or hardware-GPU behavior.

| Version | Static client and JOML linkage | Installed client, Mixins and world | Third-person main-hand terrain |
|---|---|---|---|
| 1.21.4 | PASS | PASS | Observed |
| 1.21.5 | PASS | PASS | Observed |
| 1.21.6 | PASS | PASS | Observed |
| 1.21.7 | PASS | PASS | Observed |
| 1.21.8 | PASS | PASS | Observed |

The static verifier checked both required Mixin descriptors, 28 game classes,
44 game references, and 2 JOML member references for each SHA-1-verified client
and its metadata-declared JOML 1.10.8. It rejected the 1.21.9 Mixin descriptor.
The initial pre-adaptation JAR failed on 1.21.5–1.21.8 because the quaternion and
component-getter JVM signatures changed. The candidate instead uses the matrix
operations observed in vanilla and iterates typed components; this is a
bounded implementation, not a runtime fallback.

The local world was created in 1.21.4 and opened in ascending patch order.
Screenshots: [1.21.4](1.21.4-terrain.png), [1.21.5](1.21.5-terrain.png),
[1.21.6](1.21.6-terrain.png), [1.21.7](1.21.7-terrain.png),
[1.21.8](1.21.8-terrain.png). They show terrain from one camera angle and do
not prove alignment in every pose.

Left-handed, opposite-stone and missing-data smoke checks have now been run
on every version in this group. Arm movement, complete lighting and first-person
regression, remote-player multiplayer and independent visual acceptance
remain NOT RUN across the group. Neighboring-version and wrong-Java launches are recorded below. Candidate OSV findings
and review/protection gates remain unresolved.

## Additional 1.21.4 left-handed and first-person checks

With the same candidate JAR, the local client was set to left-handed. Terrain
appeared in the [main hand](1.21.4-extra-left-main.png),
[off hand](1.21.4-extra-left-off.png), and [both hands](1.21.4-extra-left-both.png).
A map remained visible with stone in the opposite hand for the
[main-hand map](1.21.4-extra-left-main-stone.png) and
[off-hand map](1.21.4-extra-left-off-stone.png). A filled map created without
map data showed a [blank face](1.21.4-extra-left-missing.png); the client
remained running.

The [candidate first-person view](1.21.4-extra-firstperson.png) was compared
with the same Fabric Loader profile [without the candidate JAR](1.21.4-extra-firstperson-no-mod.png)
using a copy of the saved world. In the 540 by 440 pixel map crop at `(370, 60)`
the mean absolute channel difference was 0.661 on a 0–255 scale; 99.929% of
pixels differed by at most 10 levels per channel, with a maximum of 11. The
views were not pixel-identical, and this single comparison does not establish
complete first-person regression coverage.

## Unsupported-version launch

A headless Linux Fabric Loader 0.20.1 launch installed this same JAR into a
Minecraft 1.21.9 client using Java 21. Fabric exited with status 1 during mod
resolution and explicitly identified 1.21.9 as unsupported; Mixin initialization
was not reached. The [launch log](1.21.9-unsupported-neighbor.txt) records the
actual rejection. This checks the declared version guard for that client, not
a forced installation with the guard bypassed.

Headless Linux launches installed the same candidate JAR with Fabric Loader
0.20.1. Each exited with status 1 during mod resolution before Mixin
