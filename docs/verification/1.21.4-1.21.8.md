# Candidate verification: Minecraft 1.21.4–1.21.8

This is partial smoke testing, not release acceptance. Implementation source
commit `4b2e363c495640fa5ca305620c51c709a434ee2c` produced the same JAR in a
clean build and was installed unchanged on all five clients. SHA-256:
`26a28fb550132d07af415c41ccb82982937906ab991ad810406d2937b5e4e776`.

Environment: Linux x86-64, Debian OpenJDK 21.0.12.1, Fabric Loader 0.20.1,
Xorg dummy display with Mesa software GL, offline local single-player creative
world. The client could not reach account/Realms services and had no audio
device. This is not evidence of multiplayer or hardware-GPU behavior.

| Version | Static client and JOML linkage | Installed client, Mixins and world | Third-person main-hand terrain |
|---|---|---|---|
| 1.21.4 | PASS | PASS | Observed |
| 1.21.5 | PASS | PASS | Observed |
| 1.21.6 | PASS | PASS | Observed |
| 1.21.7 | PASS | PASS | Observed |
| 1.21.8 | PASS | PASS | Observed |

The static verifier checked both required Mixin descriptors, 28 game classes,
44 game references, and 2 JOML member references for each SHA-1-verified client
and its metadata-declared JOML 1.10.8. It rejected the 1.21.9 Mixin descriptor.
The initial pre-adaptation JAR failed on 1.21.5–1.21.8 because the quaternion and
component-getter JVM signatures changed. The candidate instead uses the matrix
operations observed in vanilla and iterates typed components; this is a
bounded implementation, not a runtime fallback.

The local world was created in 1.21.4 and opened in ascending patch order.

Off-hand, both maps, occupied opposite hand, left-handed setting, missing map
data, arm movement, first-person regression, remote-player multiplayer and
independent visual acceptance are NOT RUN for this group. Wrong-Java and
neighboring-version installed-client rejection are also NOT RUN. Candidate
OSV findings and review/protection gates remain unresolved.
