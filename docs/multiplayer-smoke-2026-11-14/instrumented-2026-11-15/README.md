# Instrumented 1.21.11 LAN map-data observation — 2026-11-15

Two local Fabric clients used the current proposed 1.0.0 JAR. The observer additionally loaded the retained diagnostic Java agent from [diagnostic-agent.zip](diagnostic-agent.zip), which also preserves its exact build-manifest input; the on-disk Mod JAR remained unchanged, but the agent modified `ReadableMapSurface` in memory to print the map ID and whether the client `MapItem.getSavedData` call returned a value. The [agent source](MapDataAgent.java), JVM fixture, exact input/output hashes, run commands, logs and screenshots are bound in [index.json](index.json). This is an instrumented diagnostic, not an unmodified-artifact acceptance test.

The observer initially saw the remote map with ID 2 as a [blank surface](observer-before-map.png); its logged renderer lookup returned `data_available=false`. At 13:26:54 UTC the host gave the observer map ID 2, and the observer logged its first `data_available=true` in the same second. The [observer's held map](observer-held-map.png) and the remote map after selecting an empty slot both showed [terrain](observer-after-map.png). The later observation establishes this lookup transition for this controlled repeat. It does not prove the cause of the earlier uninstrumented LAN observation or that a particular packet caused the transition: packet delivery was not instrumented, and logging can affect timing.

The observer's loopback quick-connect first encountered an authentication-service failure. The operator returned to the server list and selected the discovered LAN world, as in the earlier test; this manual UI action is not encoded in the runner. The [setup attempts](setup-attempts/) separately retain an agent with duplicate ASM classes and an agent whose helper class was not visible to Fabric. Neither reached the successful diagnostic state. The successful agent uses Java platform calls in the transformed game code and logs only to the observer process. Both clients were terminated after capture; clean shutdown, other versions, hardware-GPU and independent multiplayer acceptance remain unverified.
