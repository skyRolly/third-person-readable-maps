# Paired 26.3 world-upgrade map-ID probe — 2026-11-14

Copies of a 1.21.10-format local world were seeded in host and player inventories with explicit integer IDs 0 and 7, double 0.5, long 4294967296, a string, double NaN, and a missing component. The selected item was the fractional case; map zero contained 15,691 nonblank terrain pixels. Minecraft 26.3 upgraded each copy after the retained confirmation prompts. [Inputs](fixture.json), saved inventories, screenshots, launcher-library pins and exact runners are hashed in [index.json](index.json). The candidate used the current 1.0.0 proposal JAR; the separate control installed no Mod.

Both runs joined and saved. In both saved inventories, explicit zero and seven remained unchanged, the fractional, overflow and NaN values became integer zero, and the missing component stayed missing. The string produced the game's `Not a number` loading error; the saved slot contained a filled map with no map-ID component. The candidate's first-person and partial third-person captures show seeded map-zero terrain for the formerly fractional item; the control's first-person capture shows that terrain. The observations cover this particular world-upgrade and loading path under software rendering, not native 26.3 item data, all versions, multiplayer or full graphical acceptance.

The [setup attempts](setup-attempts/) are preserved: the first stopped during Fabric installation because the local Java trust configuration failed, and the second could not create a GLX window. The completed runs used the local trust configuration and `SDL_VIDEO_FORCE_EGL=1`, with manual upgrade confirmations recorded in the screenshots. No production world or item was changed.
