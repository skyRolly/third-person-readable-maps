# Paired 26.3 native-format map-ID loading probe — 2026-11-15

Separate copies of a world already saved in 26.3 format were seeded with explicit integer IDs 0 and 7, double 0.5, long 4294967296, a string, double NaN, and a missing map-ID component in the 26.3 player-data file. The selected item was the fractional case; map zero contained 16,249 nonblank terrain pixels. The world originated in an earlier 1.21.10-to-26.3 upgrade, but its input metadata and player data were already 26.3 format and no world-upgrade step occurred during either run. Inputs, saved inventories, screenshots, launcher pins and runners are hashed in [index.json](index.json).

Both the exact current 1.0.0 proposal JAR and no-Mod control joined and saved. Both preserved explicit zero and seven; the tested fractional, overflow and NaN values became integer zero. The string produced `Not a number` and its saved filled map lacked an ID; the absent ID remained absent. Candidate first-person and partial third-person images show map-zero terrain for the selected fractional case, and the no-Mod first-person image shows the same terrain. This is a bounded software-rendered local observation, not multiplayer, hardware-GPU or independent graphical acceptance.

The retained client matched the SHA-1 and size in the metadata, whose SHA-1 matched Mojang's version manifest. The first setup attempt failed while a Fabric installer tried direct network access; the second could not create a GLX window. Those [setup diagnostics](setup-attempts/) are preserved. The completed runs used the already installed verified client and Fabric profile with `SDL_VIDEO_FORCE_EGL=1`. No shared launcher assets or original worlds were deleted or modified.
